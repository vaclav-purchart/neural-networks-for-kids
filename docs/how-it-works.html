Neural Networks for Kids - how it works

Small neural networks, written from scratch in TypeScript, trained in Node and visualised live in the browser. This page also explains how the same ideas scale up to the large language models (LLMs) behind modern AI assistants.

1 The big picture

There are two programs that share one piece of code. The trainer runs in Node: it downloads handwriting images, teaches a network, and saves its weights. The viewer runs in the browser: it loads those weights and runs the same network on whatever you draw. The network itself lives in src/nn/, plain TypeScript with no ML libraries. Both sides import it, so training and drawing use exactly the same maths.

Two kinds of network can be trained and compared side by side in the viewer's model picker:

2 The MLP: a multi-layer perceptron

The picture becomes a list of 784 numbers (28 × 28 pixels). These flow through two hidden layers of 128 and 64 neurons and end in one output neuron per class: 10 for digits, 26 for letters. Every neuron is connected to every neuron in the previous layer, which is why it's called a dense or fully connected network. "MLP" stands for multi-layer perceptron. A perceptron is the original 1958 artificial neuron.

The hidden layers use ReLU (negative values become 0). The output layer uses softmax, which turns the raw scores into probabilities that add up to 100 %. Those are the bars on the right of the viewer.

3 What one neuron does

Each neuron does the same small calculation: multiply each input by its weight, add them all up, add a bias, then apply ReLU. That is exactly what the viewer's neuron inspector shows when you click a sphere.

4 The training loop

At first the weights are random (He initialisation with a seeded random generator), so predictions are guesses at about 10 %. Training repeats one loop thousands of times: show the network a small batch of labelled images, measure how wrong it is, work out how each weight contributed to the error, and nudge every weight slightly in the direction that would have made it less wrong.

Why "loss" and not just accuracy? Accuracy only says right or wrong. Cross-entropy, −log of the probability given to the correct answer, also says how wrong: 90 % sure and right gives a loss of 0.11, 40 % sure and right gives 0.92, and 1 % sure gives 4.6. It changes smoothly as the weights change, which is what makes it possible to compute in which direction to move each weight.

5 The backward pass, step by step

Backpropagation answers one question for every weight: "if I nudged this weight up a little, would the loss go up or down, and by how much?" That number is the weight's gradient. The update then moves each weight a small step the opposite way.

It is called backward because the cheapest way to get the answer for all 109 000 weights is to start at the output, where the mistake is visible, and pass "blame" back layer by layer through the same connections the forward pass used. Here it is on a network small enough to follow by hand: 2 inputs, 1 hidden neuron and 2 classes, where the correct answer is A.

The five steps

  1. Error at the outputs. With softmax plus cross-entropy it is simply predicted probability − target, where the target is 1 for the right class and 0 for the others. A: −0.574 means "push this score up". B: +0.574 means "push this one down".
  2. Gradients of the output weights. A weight's effect on its target is proportional to the input it carries, so gradient = input × error at the target. For v_A: 0.3 × (−0.574) = −0.172, so v_A will grow.
  3. Blame for the hidden neuron. h fed both outputs, so its error is the sum of the errors it fed into, each weighted by the connection it used. Here that's +0.574: h feeds B twice as strongly as A, so a smaller h hurts the wrong answer more than the right one.
  4. Through ReLU. The error passes back only if the neuron was active (z > 0). A neuron that output 0 gets no blame, because nudging its weights a little wouldn't change anything.
  5. Gradients of the hidden weights. Same rule as step 2: w₁ gets 1.0 × 0.574, w₂ gets 0.5 × 0.574, and the bias gets 0.574 (a bias acts like a weight whose input is always 1).

The whole algorithm in two rules
1. Weight gradient = its input × the error at its target. Weights that carried a large input get adjusted most; weights whose input was 0 aren't adjusted at all.
2. Error of a neuron = Σ (outgoing weight × error of the neuron it feeds), × 0 if ReLU was off.
Apply rule 2 layer by layer from the output back to the input, and rule 1 at every layer on the way. Mathematically this is the chain rule from calculus. One backward pass costs about as much as two forward passes.

In the code (Network.backward in src/nn/network.ts) each layer type knows its own backward step:

  • Dense: exactly the two rules above (linearWeightGrad, linearInputGrad).
  • Convolution: the same rules, but one filter weight is used at hundreds of positions, so its gradient is the sum over all of them (section 7).
  • Max-pool: only the input that won the max influenced the output, so only it receives the error. The other three get 0, which is a gate much like ReLU's.

The real code averages gradients over a batch of 64 images, which is smoother than learning from one image at a time. The test suite verifies backprop against numerical gradients: it nudges each weight by ±0.001 and measures how the loss actually changes, for both a small MLP and a small CNN.

6 Adam: how the weights are actually nudged

The simplest update is plain gradient descent: w ← w − learning_rate × gradient, as in the table above. It works, but has two problems. One learning rate rarely suits all 109 000 weights: some gradients are tiny and others large. And gradients from small batches are noisy, so steps zig-zag.

Adam ("adaptive moment estimation", Kingma & Ba, 2014) fixes both by keeping two running averages per weight:

m: momentum (average gradient)
m ← 0.9·m + 0.1·g
Smooths out noise. If the gradient keeps pointing the same way, m builds up and steps get more confident. If it flips back and forth, the flips cancel.
v: average squared gradient
v ← 0.999·v + 0.001·g²
Measures how big this weight's gradients usually are. Dividing by √v gives each weight its own scale: weights with tiny gradients still move, and ones with huge gradients don't overshoot. 
step = learning_rate × m̂ / (√v̂ + ε)        learning_rate = 0.001, ε = 10⁻⁸
m̂ = m / (1 − 0.9ᵗ),  v̂ = v / (1 − 0.999ᵗ)    "bias correction": m and v start at 0,
                                                so early averages are scaled up

In this project Adam is about 40 lines in src/nn/adam.ts and works on any list of weight tensors (Network.params()), so the MLP and the CNN use the same optimiser. LLMs use the same idea, usually AdamW, a variant that also gently pulls weights towards zero (weight decay).

7 Convolutional networks (CNNs)

The MLP treats the image as a list of 784 unrelated numbers. It has no idea that pixels are neighbours, and a stroke it learned to spot in one corner must be learned again for every other position. A convolutional network treats the image as an image. Train one with npm run train -- --dataset mnist --arch cnn.

A filter slides over the image

Three ideas make CNNs work:

  • Local connections. Each output looks only at a 3×3 patch, not the whole image. Strokes, edges and corners are local.
  • Weight sharing. The same 9 weights are reused at every position, so a pattern learned once is recognised anywhere. That's why the CNN needs only about 28 000 weights against the MLP's 109 000.
  • Stacking and pooling. Max-pooling keeps the strongest value of each 2×2 block, halving the map size, so the next layer's 3×3 filters see a larger area. Layer 1 finds edges; layer 2 combines them into curves, loops and corners. The final dense layers (an MLP) combine those into "this is a 3".

Learning in a CNN

The backward pass uses the same two rules. Weight sharing adds one twist: a filter weight was used at every position, so its gradient is the sum of "input under it × error at that output" over all positions. If the filter helped at one spot and hurt at another, the sum decides which way it moves. Max-pool passes each error only to the input that won the max.

The CNN has fewer weights but more compute, because each filter runs at hundreds of positions per image. That is why CNNs became practical with GPUs. --filters 32,64 --hidden 128 --epochs 5 trains a bigger, more accurate one (about 99 %+ on digits), at several times the training time.

Both come in the simple IDX binary format: a short header (type and dimensions) followed by raw bytes, one byte per pixel (0–255). Downloads go to a .part file first and are renamed only when complete, so an interrupted download is never mistaken for a finished one.

Centring. MNIST digits were centred by their centre of mass; EMNIST letters by their bounding box. Preparing your drawing the same way matters: on the stored test images, centring letters by mass instead of by box costs the letters MLP about 8 points and the CNN about 3. The choice is stored in each model file (preprocessing.center).

Normalisation. Pixels are scaled to 0–1. Then the dataset's average brightness is subtracted and the result is divided by its standard deviation (for MNIST, mean ≈ 0.13 and std ≈ 0.31). The mean and std are saved with the model so the browser applies exactly the same step. One side effect: a blank pixel becomes about −0.42, not 0, so blank areas do feed into the network a little.

9 Snapshots and the timeline

While training, the trainer saves copies of all the weights at fixed points. They are close together at the start, where the network changes fastest, and then come one per epoch. Each snapshot records the test accuracy at that moment, and the slider at the bottom of the viewer steps through them.

10 What happens when you draw

Every brush stroke runs the whole network again, which takes well under a millisecond, so everything updates live.

Reading the 3D view

  • MLP models: every layer is drawn as spheres, with lines for the strongest N weights per neuron (N is set in Settings).
  • CNN models: each conv layer is a grid of small glowing images, one feature map per filter, lit where that filter's pattern appears in your drawing. Pool layers aren't drawn separately, and there are no lines between maps, to keep it readable. Click a map to see its 3×3 filter weights (one small grid per input channel) and where it fires most strongly.
  • Click a sphere to see bias + Σ(input × weight) → activation and the strongest incoming and outgoing contributions. In a CNN, the first dense layer's inputs are named like "map 7 · (3, 3)".

11 A tiny transformer that writes text

The text models (npm run train -- --dataset shakespeare) use the architecture behind real LLMs, shrunk to about 113 000 weights and written by hand like the rest. The task changes from "which character is in this picture?" to "which character comes next?". The model writes text by asking that question over and over, appending its answer each time.

Tokens and embeddings

Every distinct character in the training text gets an id (Tiny Shakespeare has 65: letters, digits, punctuation, space and newline). The model can't compute with an id, so it looks up a learned list of 64 numbers for it: the character's embedding. A second learned list per position (1st, 2nd, … 64th character) is added, so the model knows where each character sits. Both tables are ordinary weights, trained by backprop.

Attention, worked through

Say the model reads "c", "a", "t" and must decide what follows "t". In one attention head, "t" builds a query and every character so far builds a key and a value (three small dense layers, as in section 12). Query·key gives a score per earlier character, a softmax turns the scores into weights, and "t" receives the weighted mix of the values:

Two details make this a language model:

  • Causal mask. A character may only look at itself and earlier characters, never later ones (they get weight 0). That's what makes it possible to generate left to right: the model never relied on text that doesn't exist yet.
  • Several heads. Each block runs 4 heads side by side, each with its own query/key/value weights, so each can learn a different habit: one looks at the previous character, another at the start of the line, another at the last space. In the viewer each head has its own color.

Blocks, residual stream and LayerNorm

A block is attention followed by an MLP (64 → 256 → 64 with the smooth GELU activation instead of ReLU). Each part adds its output to a running vector per character, the residual stream, instead of replacing it. Before each part, LayerNorm rescales the vector to mean 0 and variance 1, which keeps training stable. Our model has 2 blocks. The 3D view shows the residual stream after the embeddings and after each block: one column per stage, one thin strip per character.

Training on every position

One training example is a 65-character window of the book. The model predicts the next character at every one of the first 64 positions at once (thanks to the mask, position 10 only sees characters 1–10), so one window gives 64 labeled examples for free. Loss, error (p − one-hot) and backprop are exactly as for digits; backprop just also flows through attention. Each step uses 32 windows, and 1000 steps take about 16 minutes on a laptop CPU.

Generating: sampling and temperature

To write, the model takes the last (up to) 64 characters, computes probabilities for the next one, and picks one at random according to those probabilities. Before the softmax, the scores are divided by the temperature: below 1 the favorite wins more often (safe and repetitive), above 1 the odds even out (creative, then nonsense). Then the new character is appended and everything repeats.

In the viewer, pick the Shakespeare model, type ROMEO: and press Step repeatedly: the 3D network lights up one part at a time (text → embedding → attention → MLP → block 2 → output → pick) and a caption explains each with the real numbers. Play runs the steps by itself; at high speed it just writes. Click any character to see its own prediction, and drag the timeline to compare an untrained model (flat attention, random output) with the trained one.

12 From here to large language models

An LLM uses the same ingredients as this project, and section 11 already showed a tiny one: neurons, weights, nonlinearities, softmax, cross-entropy, backprop and an Adam-style optimiser. What changes is the architecture (the transformer), the task (predicting the next piece of text) and the scale.

Attention: connections computed on the fly

In our networks the connections are fixed after training: pixel (14, 14) always reaches hidden neuron #5 with the same weight. Language needs something more flexible. In "The cat sat because it was tired", the model must work out that "it" refers to "cat", and that link depends on the sentence. Attention lets every token decide, from the input itself, how much to look at every earlier token.

How one attention step works, for each token:

  1. Three small dense layers turn the token's vector into a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what I'll pass on").
  2. The token's query is compared with every earlier token's key (a dot product). Large means relevant.
  3. A softmax turns those scores into weights that sum to 1. This is the same softmax as our output layer.
  4. The token receives the weighted sum of the earlier tokens' values. "it" now carries information about "cat".

Many attention "heads" run side by side, each free to learn a different kind of relation (grammar, references, topic). Then each token goes through an MLP block, which is the kind of network this project builds. Each layer adds its result to a running "residual stream" instead of replacing it. That lets the error signal reach the early layers of a very deep stack without fading, and it's why LLMs can have a hundred layers while a plain MLP gets hard to train beyond a few.

Where CNNs fit: they are built for grid-shaped data like images and dominated computer vision from about 2012 to 2020. Transformers now handle images too: a Vision Transformer cuts an image into patches and treats them like tokens. The MLP, the simplest building block, lives inside both: as the dense head at the end of a CNN, and as the feed-forward block in every transformer layer.
